# 公开发布与隐私处理

公开版提供应用源码、文档、合成演示生成器和测试，不发布企业业务快照。README 中的功能和部署说明应与当前实现一致。

## 发布前

~~~powershell
git status --short
git diff --check
python scripts/check_public_source.py
git log --format=fuller -1
~~~

确认当前提交的作者与提交者使用各自的 GitHub noreply 邮箱。检查程序只检测常见模式，不能识别所有敏感信息；发布者仍需审阅文件、提交消息和新增附件。

## 排除内容

企业 Excel、真实客户和订单明细、库存和产能统计、数据库、运行日志、导出文件、个人路径、真实邮箱、密钥及环境变量文件不进入公开源码。

生成器输出到 .var/，应用数据库和本地运行数据也保存在该目录；这些内容由 Git 忽略。gitignore 不能撤回已经跟踪或已经上传的文件。

## 处理历史暴露

替换包含个人邮箱的提交，需要重建干净历史并更新远端分支。更新前应核对远端提交，使用 force-with-lease 避免覆盖队友的新工作。替换后，旧克隆需要重新克隆或由维护者协助同步；不要从旧克隆重新推回被清理的历史。

历史重写能清理当前分支记录，不能撤回他人已经保存的副本；旧提交也可能仍能通过已知 SHA 或 GitHub 缓存访问。必要时由账户持有人联系 GitHub Support 处理缓存。公开分发无法提供绝对的撤回保证。

## 后续上传

只推送经过审阅的 main 或功能分支，不使用 git push --all 或 --mirror 发布本地归档引用。新增数据示例需明确为合成数据，避免把企业实际统计写进公开文档。
