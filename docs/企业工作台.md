# 新大地 APS 企业工作台

本阶段交付工厂工作台和版本流转。React 页面调用 FastAPI，后台求解器复用已验算的排程内核。SQLite 用于本机试点，生产数据库配置为 PostgreSQL。演示入口和正式账户使用不同登录方式。

## 本机启动

在项目根目录执行以下命令。前端构建产物由 FastAPI 在同一地址提供。

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-product.txt
npm --prefix frontend ci
npm --prefix frontend run build
.\.venv\Scripts\python.exe scripts/create_demo_workbook.py
.\.venv\Scripts\python.exe -m aps.product serve --demo --source .var/demo.xlsx
~~~

访问 http://127.0.0.1:8010/，选择「计划员」。Excel 可从数据接入页面上传，传入样本路径时也可从对话框读取。原始样本不会随源码分发。浏览器里按以下顺序演示。

1. 导入数据，检查有效产线、订单和异常，并下载对账。
2. 新建排程，对比本批方案，在甘特图里打开批次，查看订单证据。
3. 计划员提交审批。切换为审批主管，批准后发布。含未排任务的方案应填写处置说明。
4. 切换为车间班组，确认签收。操作记录可核对角色、时间、版本和备注。
5. 在计划视图打开草案，拖动作业，或点击作业后填写目标产线和开工时间。通过生产约束校验后保存成新草案。锁定的作业会在重排时维持产线及工期，遇到冲突时需重新核对。解锁也会保留原版本。
6. 在车间报工页筛选当前已签收版本。登记实际开工、结束和合格完成量。实际已开工但零完成量可填 0，尚未开工可登记确认时点。更正报工会记录前后结果。
7. 按报工重排会沿用报工页的核对时点。该时点前的作业需要有实际结批或有效的未开工确认。已报产量成为历史，剩余量重新排程。提交或发布前有新的报工时，需按新记录重新生成方案。异常重排也支持插单、停机及物料延期。

## 私有化部署配置

在部署机设置 .env 文件中的 APS_DB_PASSWORD、对应的 URL 编码 APS_DB_PASSWORD_URL。启用 HTTPS 入口时设置 APS_SECURE_COOKIE=1。运行 docker compose up -d --build。容器先运行 Alembic 迁移，API 与 Worker 共享 PostgreSQL，默认由宿主机 127.0.0.1:8010 接入反向代理。根据角色创建账户，例如 docker compose exec api python -m aps.product create-user planner 张三 planner。账户创建命令从终端读取密码。

本地数据库存放在 .var/product.sqlite3，可以通过 APS_PRODUCT_DATABASE 指向隔离库。例行备份需要覆盖派工版本、数据快照和账户，恢复后用工厂账户进行流程复验。

## 本阶段验证范围

- 后台求解任务有工厂范围、幂等键、认领超时和失效 Worker 结果保护。审批、发布、签收使用版本检查并写日志。系统通过当前活跃计划指针表示发布结果，车间账户仅可见已发布及已签收的方案。
- 订单排程证据来自经校验的版本，提供原始数量、库存、产线、时间和未排原因。LLM 读数与试算建议将在真实工厂问例和数据权限确认后接入。
- Excel 是可用的数据通道，当前可在工作台手工登记和更正报工。生产账户只能发布基于正式输入的初始方案或基于车间报工的重排。企业 ERP/MES 连接器、批量报工导入、企业身份对接和 PostgreSQL 行级策略按试点范围推进。
- 自动回归使用 requirements-test.txt，然后运行 python -m unittest discover -s tests -v。旧版演示仍可通过 python -m aps serve 启动。
